# atlassian_jsm_form_template (Data Source)

Reads an Atlassian Forms project template by project and UUID, using Basic authentication and automatic cloud ID discovery. Returns the complete design as reusable request JSON (default-answer users become account IDs), plus publishing settings.

## Example Usage

```terraform
data "atlassian_jsm_form_template" "joiner" {
  project_id = "10001"
  id         = "c18bde7a-d846-11ed-afa1-0242ac120002"
}

output "joiner_design" {
  value = jsondecode(data.atlassian_jsm_form_template.joiner.design)
}
```

## Schema

### Required

- `id` (String) The form template UUID.
- `project_id` (String) Jira project ID or key (not service desk ID).

### Read-Only

- `design` (String) Normalized JSON FormDesignRequest: conditions, layout, questions, sections and settings. Link compatible existing Jira fields with questions.<id>.jiraField. Layout is opaque ADF; supply a known valid design. Object order and whitespace are insignificant; array order is preserved. Optional API defaults absent from configuration are ignored on refresh.
- `publish` (String) Normalized JSON FormPublishing. Set portal.portalRequestTypeIds to numeric request type IDs, plus portal.submitOnCreate and portal.validateOnCreate. Omit to retain API settings; use explicit empty ID arrays to unpublish. This does not manage native request-type fields or remove Summary.
