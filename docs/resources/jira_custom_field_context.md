# atlassian_jira_custom_field_context (Resource)

Manages a Jira custom field context. Requires Administer Jira. Import existing contexts instead of creating overlapping contexts. Deleting a context can delete its options and affect issue values.

## Example Usage

```terraform
resource "atlassian_jira_custom_field_context" "example" {
  field_id       = "customfield_10000"
  name           = "Project-specific choices"
  description    = "Choices for the selected project"
  project_ids    = ["10001"]
  issue_type_ids = [] # All issue types within the selected project.

  lifecycle {
    prevent_destroy = true
  }
}
```

## Schema

### Required

- `field_id` (String) The custom field ID. Changing this replaces the context.
- `name` (String) The context name.

### Optional

- `description` (String) The context description.
- `issue_type_ids` (Set of String) Issue type IDs. An empty set applies to all issue types. Changing scope replaces the context and may delete its options. Global contexts cannot be destroyed or replaced. Use prevent_destroy for existing contexts.
- `project_ids` (Set of String) Project IDs. An empty set creates a global context. Changing scope replaces the context and may delete its options. Global contexts cannot be destroyed or replaced. Use prevent_destroy for existing contexts.

### Read-Only

- `id` (String) The context ID.

## Import

Import is supported using the following syntax:

```shell
terraform import atlassian_jira_custom_field_context.example customfield_10000/10100
```
