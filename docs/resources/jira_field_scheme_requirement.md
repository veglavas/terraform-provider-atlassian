# atlassian_jira_field_scheme_requirement (Resource)

Manages the required flag for one field and issue type in an existing Jira field association scheme using the experimental Field schemes API. The field must already be associated with the scheme and available to the issue type. Does not manage screens, field associations, or native JSM request-form field selection. Destroy removes only this issue type's isRequired override, restoring inheritance from the scheme default; it does not restore a previous override. Schemes may be shared by multiple projects.

## Example Usage

```terraform
# Discover the existing scheme; it may be shared with other projects.
data "atlassian_jira_project_field_scheme" "example" {
  project_id = var.project_id
}

# The field must already be associated and available to this issue type.
resource "atlassian_jira_field_scheme_requirement" "example" {
  scheme_id     = data.atlassian_jira_project_field_scheme.example.id
  field_id      = var.field_id
  issue_type_id = var.issue_type_id
  is_required   = true
}

# Destroy restores inheritance from the scheme default, not an earlier override.
# Native JSM request-form visibility and ordering are not managed here.
```

## Schema

### Required

- `field_id` (String) Existing associated Jira field ID, such as customfield_10000. Changing this requires replacement.
- `is_required` (Boolean) Whether this field must be supplied for this issue type. Reads the effective value, falling back to the scheme default when no required override is returned.
- `issue_type_id` (String) Issue type (work type) ID whose required flag is managed. Other issue types and scheme defaults are untouched. Changing this requires replacement.
- `scheme_id` (String) Existing field association scheme ID. All projects sharing this scheme are affected. Changing this requires replacement.

### Read-Only

- `id` (String) Composite ID: SCHEME_ID:FIELD_ID:ISSUE_TYPE_ID.
