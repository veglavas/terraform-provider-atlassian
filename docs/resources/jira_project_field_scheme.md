# atlassian_jira_project_field_scheme (Resource)

Manages a project's field scheme assignment using the experimental Field schemes API. Requires Administer Jira. Import by project ID. Jira exposes assignment, not unassignment: by default destroy retains the remote assignment and relinquishes Terraform ownership. Set on_destroy_scheme_id to explicitly reassign to a known existing fallback on destroy. There is no hardcoded default and no automatic restoration of an earlier scheme. An assigned scheme cannot be deleted until the project is reassigned or deleted.

## Example Usage

```terraform
resource "atlassian_jira_project_field_scheme" "managed" {
  project_id = "10002"
  scheme_id  = atlassian_jira_field_scheme.managed.id

  # Explicit fallback on destroy. Omit to retain the remote assignment.
  on_destroy_scheme_id = "90000"
}
```

## Schema

### Required

- `project_id` (String) Project ID; also the import ID. Changing it requires replacement.
- `scheme_id` (String) Managed field scheme ID. Changes reassign the project in place.

### Optional

- `on_destroy_scheme_id` (String) Explicit existing fallback scheme to assign on destroy. When omitted the assignment is retained, which can block deletion of the assigned scheme. This is local destroy policy, not a remotely readable attribute.

## Import

Import is supported using the following syntax:

```shell
terraform import atlassian_jira_project_field_scheme.managed 10002
```
