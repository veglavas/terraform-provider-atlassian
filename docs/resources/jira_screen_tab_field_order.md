# atlassian_jira_screen_tab_field_order (Resource)

Manages the order of all fields on a Jira Cloud screen tab through documented public APIs. It configures Jira and agent-side JSM Create/Edit screens only; native JSM customer-portal request forms and the modern issue-view layout have independent layouts this resource does not control. The field_ids list must enumerate the tab's complete membership exactly once, in the desired order from first to last; field membership itself stays owned by atlassian_jira_screen_tab_field resources, which this resource never adds or removes. Creation and updates wait up to 30 seconds for field membership to become visible before any move, then verify the resulting order with a separate bounded wait. Use exactly one atlassian_jira_screen_tab_field_order resource per tab and depend on every field placement for that tab, so placements exist before ordering and destroy relinquishes ordering before removing the fields. Destroying this resource relinquishes order ownership only: no fields are removed or reordered, because a field order is not a deletable Jira object and restoring an unknown previous order would be destructive.

## Example Usage

```terraform
# Field membership stays owned by atlassian_jira_screen_tab_field resources.
# This resource orders the fields that those resources place on the tab.
resource "atlassian_jira_screen" "example" {
  name = "Example Screen"
}

resource "atlassian_jira_screen_tab" "example" {
  screen_id = atlassian_jira_screen.example.id
  name      = "Details"
}

resource "atlassian_jira_screen_tab_field" "summary" {
  screen_id = atlassian_jira_screen.example.id
  tab_id    = atlassian_jira_screen_tab.example.id
  field_id  = "summary"
}

resource "atlassian_jira_screen_tab_field" "department" {
  screen_id = atlassian_jira_screen.example.id
  tab_id    = atlassian_jira_screen_tab.example.id
  field_id  = "customfield_10001"
}

# field_ids must list every field on the tab exactly once, in the desired
# order from first to last. depends_on guarantees all placements exist before
# the order is reconciled, and makes destroy relinquish ordering before the
# placements are removed.
resource "atlassian_jira_screen_tab_field_order" "example" {
  screen_id = atlassian_jira_screen.example.id
  tab_id    = atlassian_jira_screen_tab.example.id

  field_ids = [
    "summary",
    atlassian_jira_screen_tab_field.department.field_id,
  ]

  depends_on = [
    atlassian_jira_screen_tab_field.summary,
    atlassian_jira_screen_tab_field.department,
  ]
}
```

## Schema

### Required

- `field_ids` (List of String) The complete, ordered list of field IDs on the tab, first to last, listing each member exactly once. An empty list is valid only for a tab with no fields. Unknown values during planning (e.g. custom field IDs from other resources) are fine once they resolve at apply time.
- `screen_id` (String) The ID of the screen that owns the tab. Changing this replaces this order controller only; the tab's field membership is never modified.
- `tab_id` (String) The ID of the screen tab whose fields are ordered. Changing this replaces this order controller only; the tab's field membership is never modified.

### Read-Only

- `id` (String) Synthetic ID in the format {screen_id}/{tab_id}.

## Import

Import is supported using the following syntax:

```shell
# Import the current field order of a screen tab.
# ID format: {screen_id}/{tab_id}
#
# The imported field_ids reflect the remote order at import time; make sure the
# configuration lists the exact same membership before the next apply.
terraform import atlassian_jira_screen_tab_field_order.example 10001/20001
```
