# atlassian_jsm_form_template (Resource)

Manages an Atlassian Forms project template using the public Forms API and the provider's Basic authentication. The cloud ID is discovered automatically. Requires the documented Jira administration permission for writes. See the Forms specification for layout and field-linking limitations. Creation is never automatically retried; reconcile an ambiguous failure before applying again.

## Example Usage

```terraform
# Reuse a valid existing design through the documented GET endpoint.
# The public OpenAPI layout example is only [{}]; it cannot bootstrap a
# useful question layout. See docs/spec/jsm-form-templates.md.
variable "project_id" { type = string }
variable "source_template_id" { type = string }
variable "request_type_id" { type = string }
variable "employee_question_id" { type = string }
variable "employee_custom_field_id" { type = string }

data "atlassian_jsm_form_template" "source" {
  project_id = var.project_id
  id         = var.source_template_id
}

locals {
  source_design = jsondecode(data.atlassian_jsm_form_template.source.design)
}

resource "atlassian_jsm_form_template" "example" {
  project_id = var.project_id
  design = jsonencode(merge(local.source_design, {
    settings = merge(local.source_design.settings, { name = "Equipment request" })
    questions = merge(local.source_design.questions, {
      (var.employee_question_id) = merge(local.source_design.questions[var.employee_question_id], {
        # Existing compatible Jira field; preserve the source question and layout.
        jiraField = var.employee_custom_field_id # e.g. customfield_10042
      })
    })
  }))
  publish = jsonencode({
    portal = {
      portalRequestTypeIds = [tonumber(var.request_type_id)]
      submitOnCreate       = true
      validateOnCreate     = true
    }
  })
}
```

## Schema

### Required

- `design` (String) Normalized JSON FormDesignRequest: conditions, layout, questions, sections and settings. Link compatible existing Jira fields with questions.<id>.jiraField. Layout is opaque ADF; supply a known valid design. Object order and whitespace are insignificant; array order is preserved. Optional API defaults absent from configuration are ignored on refresh.
- `project_id` (String) Jira project ID or key (not service desk ID). Prefer the stable project ID. Changing this replaces the template.

### Optional

- `publish` (String) Normalized JSON FormPublishing. Set portal.portalRequestTypeIds to numeric request type IDs, plus portal.submitOnCreate and portal.validateOnCreate. Omit to retain API settings; use explicit empty ID arrays to unpublish. This does not manage native request-type fields or remove Summary.

### Read-Only

- `id` (String) The form template UUID.
